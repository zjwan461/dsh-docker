### 这个模板的两个卖点（每篇都要体现，别只讲"跑起来"）

**卖点一：它真的能跑起来。** 7 层适配链（网络入口 / 信任围栏 / 沙箱 / 持久化 / 设置页补丁 / profile 投影 / 构建自检），每层都给出原因和解法。

**卖点二：跑起来之后它真的有用。** 镜像里预装了让 agent 能交付成果的能力：
- **Python 文档能力**：`python-pptx` / `python-docx` / `openpyxl` / `Pillow` ⇒ agent 能用 Python 脚本完成更复杂的工作，**交付一份文件**而不只是给一段文字；
- **媒体与 PDF 能力**：`ffmpeg` / `sox` / `imagemagick` / `exiftool` / `poppler-utils` / `qpdf` / `ghostscript` ⇒ 转码、抽帧、缩略图、音视频处理、PDF 转换合并；
- **文档转换**：LibreOffice（组件包）+ pandoc；
- **中文字体**：`fonts-noto-cjk` ⇒ 没它中文文档转 PDF 就是满屏方框；
- **内置插件机制**：`plugins/` 下每个目录启动期自动启用，附带一个登录门禁。

> 一句话口径：**"能跑"只是及格线，预装这些能力才让它从"能聊天"变成"能交付"。**

### ⛔ 写作纪律：别写自我泄气的句子（踩过）

**这一类句子一律不许进正文**——它们来自工程笔记里的自我备忘，读者不关心我的开发机装了什么：

| 不许写 | 为什么 | 改写方向 |

## 一、架构与网络

| 事实 | 值 / 原文 |
|---|---|
| 服务数量 | **两个容器**：`dsh`（业务）+ `caddy`（唯一网络入口）。**没有第三个。** |
| 对外端口 | **只有 443 一个**（README 原话：`只有一个对外端口:443，只服务一个站点`） |
| 链路 | `浏览器 ──HTTPS(443)──> caddy ──HTTP(compose 内网)──> dsh:3080` |
| dsh 容器是否发布端口 | **不发布**。`EXPOSE 3080` 仅为文档性质 |
| Caddy 同时承担 | 域名虚拟主机 + TLS 终结 + 反向代理 |
| compose 网络名 | `dsh`（driver: bridge） |
| 命名卷 | 只有 `caddy-data`、`caddy-config` 两个 |
| GUI 状态持久化 | 目录 bind mount `./data/dsh:/data/dsh`（**不是**命名卷） |
| 工作区挂载 | `${DSH_WORKSPACES:-./workspaces}:/workspaces` |
| `stop_grace_period` | `15s`（dsh SIGTERM 最多优雅退出 5 秒） |
| healthcheck 期望码 | `200` 或 `401`，`start_period: 90s` |
| README 文件清单收录 | `Dockerfile` `entrypoint.sh` `doctor.mjs` `compose.yaml` `Caddyfile` `.env.example` `verify.sh` `data/dsh/settings.yaml` `patch-client-settings.mjs` `workspaces/` `skills/` `LICENSE` —— **已不含 `admin/`** |

### 一处重要的仓库状态：`admin/` 已从编排里移除

- `compose.yaml` **不再有 `admin` 服务**，也**不再有 `admin` profile**；README 里那两节「管理端」已整节删除。
- 但 `admin/` 目录**仍在磁盘上**（含 `app/`、`tests/`、`static/`、甚至一个 Windows 版 `.venv/`），**属于未被引用的残留**，会被 `docker compose build` 忽略。
- 移除它的收益是真实的：那个面板为了读 `dsh` 容器的启动日志以提取登录令牌，**必须挂 `/var/run/docker.sock`**——那等价于宿主机 root。这是它与"只是读日志"不相称的一项权限。
- 因此**文章里不要再介绍管理端**。如果观众问"以前那个看 token 的面板呢"，正确答案是：现在用
  ```bash
  docker compose logs dsh | grep -o 'token=[A-Za-z0-9._-]*' | tail -1
  ```
  （注意 `docker logs` 跨重启保留，可能匹配到旧令牌，所以要配合"服务是否重启过"来判断。）

## 三、认证与凭据（最容易写错的一节）

| 事实 | 值 |
|---|---|
| 登录令牌长度 | base64url **43 字符**（`randomBytes(32)`） |
| 令牌是否落盘 | **否**，只在内存；每个进程启动重新生成 |
| 令牌是否有过期时间 | **没有**。进程不重启就一直有效 |
| 令牌只在哪被接受 | **不带其他参数的 `GET /`**（`pathname === "/" && tokens.length === 1`） |
| Cookie 算法 | HMAC-SHA256 签名，形如 `v1.<payload>.<sig>` |
| Cookie 标志 | `HttpOnly; SameSite=Strict; Path=/` —— **没有 `Secure`** |
| Cookie 签名密钥位置 | `$DSH_HOME/.credentials.yaml`（宿主 `data/dsh/.credentials.yaml`），32 字节随机，只在缺失时生成 |
| Cookie 默认有效期 | **30 天**（`cookieMaxAgeDays`，最小 1） |
| Cookie payload 绑定 | 归一化后的 `authority`（`host:port`）⇒ 换域名/换端口旧 cookie 失效 |

**吊销全部会话的唯一方法**：

```bash
docker compose exec dsh rm /data/dsh/.credentials.yaml && docker compose restart dsh
```

**重启对已登录浏览器的影响**：**仍然有效**（密钥持久且未过期）。重启只换令牌。

> 想延长 cookie 有效期：在 `data/dsh/cordis.patch.yml` 里追加 `connection` 行并设 `cookieMaxAgeDays: 365`。
> ⚠️ 补丁层可能是**替换**而非合并语义，所以 `trustedHosts: !!js ctx.webRuntime.trustedHosts` **必须一并重复声明**，否则信任围栏失效、所有访问变 403。

## 四、信任围栏（403 的唯一原因）

```js
// 无端口条目 -> 只比 hostname；带端口条目 -> 比 host:port
return canonical === entryUrl.hostname
  ? entryUrl.hostname === hostUrl.hostname
  : entryUrl.host === hostUrl.host;
```

| 事实 | 结论 |
|---|---|
| `DSH_TRUSTED_HOSTS` 正确写法 | **裸 authority**，如 `dsh.example.com` |
| 写成 `dsh.example.com:443` | **永远匹配不上**（浏览器默认端口不带端口号） |
| 裸域名是否对任意端口成立 | **是** |
| 写成 `https://域名` 或带路径 | 插件加载直接报错 |

## 五、沙箱

| 事实 | 值 |
|---|---|
| Linux 沙箱链 | `bwrap → Landlock`，按序探测 |
| 两者都不可用 | **fail closed**：`SANDBOX_UNAVAILABLE`，不裸跑 |
| 镜像为什么故意不装 bubblewrap | 容器里 bwrap 需要非特权 user namespace + 放宽的 seccomp；不装则确定性落到无需特权的 Landlock |
| 生效证明（实测日志） | `landlock launcher full (/usr/.../landlock-run)`；有的内核报 `partial`——**可接受** |
| `partial` 与 `unusable` 的区别 | `partial` = 内核 Landlock ABI 较旧，文件写入仍受限，部分新权限位不受治理；`unusable` = 完全不可用，`workspace-write` 会 fail closed |
| launcher 二进制缺失的含义 | 平台包 `@deepseek-ai/node-addon-system-<os>-<arch>` 不在——npm 只按**构建时**平台装这个可选依赖，所以**构建架构 ≠ 运行架构**时会这样。解法：在本机 `docker compose build --no-cache dsh` |
| doctor 的退出码 | **永远是 0**（沙箱坏掉不能阻止 GUI 启动） |
| 验收命令 | GUI 里让 agent 写工作区外路径 → `[sandbox: file access denied under workspace-write mode]` |
| **关键边界** | `workspace-write` **只限制写文件；读和网络不受限** |
| `danger-full-access` 额外效果 | **同时**把审批策略变成 `never` |

### 5.1 ⭐ 实测：ARM64 上得到的是 `unusable`（文章里要写这段）

**事实**（来自 `img/docker_compose_log.png` 那张真实日志，ARM64 小机器）：

```
dsh doctor: node v22.23.3; landlock launcher unusable
  (/usr/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/node-addon-system-linux-arm64/bin/landlock-run)
dsh doctor: WARNING no usable Landlock runner on this kernel. workspace-write will fail closed with
SANDBOX_UNAVAILABLE. Fix: host kernel >= 5.13 with the landlock syscalls allowed by the container seccomp
profile (recent Docker/containerd default profiles allow them). Alternative: set
DSH_PERMISSION_MODE=danger-full-access, which drops file confinement AND the approval prompt, so the
container becomes the only boundary.
dsh starting: node ... web --patch ... --no-open --trusted-host <IP>     ← 无 --permission-mode，说明走了 full-access
```

| 要点 | 说明 |
|---|---|
| 结论词 | **`unusable`，不是 `partial`**。三个词的语义严格不同：`full`（完整）/ `partial`（能用但 ABI 旧，**文件仍受限**，可接受）/ `unusable`（**这一层根本不在**，fail closed） |
| `unusable` 时怎么办 | ① 宿主内核 ≥ 5.13；② 容器 seccomp 放行 landlock 系统调用；③ 否则只能退 `danger-full-access` |
| `danger-full-access` 的**双重**代价 | **文件约束没了 + 审批提示也关了**（日志原话：`drops file confinement AND the approval prompt, so the container becomes the only boundary`）⇒ 挂载面必须收到最小 |
| 架构线索 | launcher 路径是 `node-addon-system-linux-arm64` ⇒ 该机器是 **ARM64**（终端提示符另显示为树莓派） |
| ⚠️ **无法从日志区分的原因** | `unusable` 到底是**内核/seccomp 不允许**，还是**平台包不对**，日志里分不出来。文章里必须标为"需要你自己进一步查"，不能下结论 |
| 未验证 | **NodeSource 的 Node 22 在 ARM64 上的可用性**，以及 `node-addon-system-linux-arm64` 是否真的装成功——都要在目标机上验证（`docker compose exec dsh node -v` + `grep 'landlock launcher'`） |

**文章里的正确写法**：把这段作为**真实的失败经历**写，并明确指出它**恰好验证了 fail closed 设计**（不静默降级、把结论打进日志、给出完整修法与替代方案的代价）。**不要**写成"沙箱一定生效"，也不要隐瞒。CSDN 第 4.1–4.3 节、今日头条第 8 段、B站 08:00–08:50 段就是这么处理的。

## 六、profile 投影（坑六）

| 事实 | 值 |
|---|---|
| profile 的 `package.json` dependencies | **空**（`{}`），插件集由 `dsh.profile.bundles` 指定 |
| 插件如何就位 | 启动时从**安装树**投影（symlink）到 `$DSH_HOME/profiles/node_modules` |
| 运行时是否需要 npm registry | **不需要**，所以"没有东西可以预装" |
| `dsh plugin --profile web install` 的结果 | `Already up to date`（构建里实测原话，`Done in 919ms using pnpm v12.11.2`） |
| 投影不完整的后果 | 遮蔽安装树 ⇒ 每次重启都 `plugin(s) failed to load: @deepseek-ai/dsh-sandbox-local; could not be resolved` |
| 为什么 chown 不管用 | **坏的是内容，不是权限**；而 profile 没有依赖 ⇒ 没有东西会重建它 |
| 唯一修法 | `rm -rf data/dsh/profiles/node_modules && docker compose restart dsh` |
| 完整投影的包数量级 | 约 **250** 个 `@deepseek-ai/*` 包 |

## 七、预发布版本漂移

| 事实 | 值 |
|---|---|
| 机制 | 各包之间用 `^0.1.5-rc.1` 这类范围互依赖，npm 解析到**该范围内最新的预发布版** |
| 后果 | CLI 停 rc.1、`dsh-base` 浮到 rc.3 ⇒ 混装 ⇒ 部分包不在安装树顶层 ⇒ 启动必失败 |
| 规则 | **`DSH_VERSION` 用该系列里最新的那个**（范围没有更新的可浮） |
| semver 保护 | 范围被限制在同一版本 tuple 内，`0.1.6-alpha.x` 之类的进不来 |
| 为什么 `--dump-config` 抓不到 | 它**只组合配置、不 import 插件模块**，坏树照样"成功" |
| 额外实测事实 | **显式 pin 的包落在 npm 全局根**，**CLI 的依赖嵌套在它旁边**（`.../dsh/node_modules/@deepseek-ai/`）；Node 两处都能解析，所以构建期断言**两处都查** |

## 八、设置页补丁（坑七）

| 事实 | 值 |
|---|---|
| 上游定义（逐字） | `isLoopback: transport?.ownsHost === true \|\| pageLocation === void 0 \|\| isLoopbackHostname(pageLocation.hostname)` |
| 消费者位置 | `dsh-client-ui-settings` 与 `dsh-client-ui-settings-general`（**两处独立门禁，读同一个定义**） |
| 报错文本 | `Loading the provider directory failed: settings are available in this browser` |
| 补丁改法 | 把那个定义整体改成 `true`（带 `/* PATCHED by dsh-docker: … */` 注释） |
| 何时应用 | **构建期，以 root**（Dockerfile:438）；启动期只 `--check` 复核 |
| 为什么不能运行时改 | 目标文件在 **root 所有的 npm 全局安装树**里；profile 的 `node_modules` 只是指向它的符号链接 ⇒ 运行时必然 `EACCES`（`cannot stage a file in … (EACCES)`） |
| 为什么不用编译 | `dsh-client-modules` 从磁盘读 `lib/client.js` 并以 `plugins/<id>/client.js` 提供 ⇒ **改文件就是改浏览器执行的东西** |
| 锚点策略 | **整条表达式**，不用行号；匹配 0 次或 >1 次都判失败 |
| 幂等判据 | 子串 `PATCHED by dsh-docker`（不是重新匹配锚点） |
| 语法校验 | 用 `vm.Script`，**不是 `node --check`**。理由两条：`node --check` 会拒绝对不认识的扩展名做检查（早期把暂存文件命名 `.tmp` 时这道门每跑必失败）；且它从最近的 `package.json` 推断模块系统，而浏览器把它当**经典脚本** |
| 写入方式 | 在**目标同目录**暂存再 `rename`。理由：pnpm 用**硬链接**从内容寻址存储取包文件，原地写会污染共享副本；`/tmp` 可能不可写或跨文件系统（`EACCES` / `EXDEV`） |
| 搜索策略 | ① 用 Node 解析器找包；② 退回**跟随符号链接**的遍历——pnpm 的 `node_modules` 全是符号链接，而 `Dirent` 的 `isDirectory()/isFile()` 对链接**都是 false** |
| 失败是否致命 | **不致命，只告警**；GUI 照常工作，仅设置页退化 |
| 副作用（必须说明） | 远端浏览器**能读写 provider 凭据**（`settings.yaml` 的 apiKey）。服务端围栏不变，但"谁能改 key"的范围扩大了 |

**锚点原文**：

```js
const ANCHOR = /(isLoopback:\s*)transport\?\.ownsHost === true \|\| pageLocation === void 0 \|\| isLoopbackHostname\(pageLocation\.hostname\)(,)/g;
```

**失败时的诊断输出（逐字）**：

```
The upstream bundle changed. Find the new form with:
  grep -n 'isLoopback' <paths...>
then update ANCHOR in this script. Do not fall back to a line number.
```

## 九、镜像内容：这是"能跑"与"有用"的分界线

### 9.1 三层能力（文章要突出这一节的价值）

| 层 | 内容 | 解锁了什么 |
|---|---|---|
| **基础工具** | `curl` `wget` `rsync` `git` `openssh-client` `unzip/zip/p7zip/bzip2/zstd/xz` `file` `jq` `tree` `sqlite3` `vim-tiny` `nano` `less` `procps` `tini` `ripgrep` `iproute2` `bind9-dnsutils` `iputils-ping` `netcat-openbsd` `tzdata` | 下载、解包、查看、**容器内编辑**（没编辑器就只能 `docker cp`）、排障、时区 |
| **文档 / PDF / 媒体** | `poppler-utils`（`pdftotext`/`pdftoppm`/`pdfinfo`）、`qpdf`、`ghostscript`、`imagemagick`、**`ffmpeg`**、`sox`、`libimage-exiftool-perl`、`fonts-dejavu-core` **`fonts-noto-cjk`** `fonts-noto-color-emoji` | PDF 转文本/转图/合并/线性化；**视频转码、抽帧、缩略图**；音频裁剪重采样拼接；EXIF 读写；**中文不出豆腐块** |
| **Python 文档 + 数值能力** | 文档：`python-pptx` `python-docx` `openpyxl` `Pillow`；数值：`numpy` `pandas` `scipy` `matplotlib`（Agg 后端）；抓取/解析：`requests` `beautifulsoup4` `lxml` `PyYAML`（`INSTALL_PYTHON_DOCS=1`） | 让 agent **构造** Office 文档（PPT/Word/Excel + 图片）而不是只输出文本；**直接算数据、直接画图存文件**（中文标签可选用 `fonts-noto-cjk`）；写脚本不用先 `pip install` |

### 9.2 关于 Python 的正确表述（⚠️ 必须改对，别写成"Python 没用"）

- **错的写法**：*"Python 解释器在这个栈里已经没有任何用途，只是碰巧用了这个镜像。"*
- **对的写法**：Dockerfile 注释的原话是
  > `The Python interpreter itself is no longer used by anything in this stack. The base is kept deliberately: it is the configuration that is proven on the target host`

  它说的是"**选 Debian 这个基线，不是冲着 Python 去的，而是因为它已被验证过、能拿到预编译的 glibc 原生依赖**"——那是在解释**基线选择**，不是在否定 Python。
- **正确的定位**：Python 解释器**随基础镜像白拿**，而 `INSTALL_PYTHON_DOCS` 那批库**把它从"白搭"变成了 agent 的真实能力**。一句话：**零边际成本，把白拿的东西变成生产力。**
- **关键细节**：`python-pptx` + `Pillow` **正是让 agent 能生成带图 PPT 的那两个库**。没有它们，agent 面对"做一份幻灯片"只会回"请先 `pip install python-pptx`"——而容器里的 `pip install` 要出网、要等，没有外网就直接无解。
- **这层现在是两组库**：文档生成（`python-pptx` `python-docx` `openpyxl` `Pillow`）**加**日常数值栈（`numpy` `pandas` `scipy` `matplotlib`）与抓取/解析库（`requests` `beautifulsoup4` `lxml` `PyYAML`），合计 **约 200–250MB**。`matplotlib` 通过 `ENV MPLBACKEND=Agg` 固定后端，无显示设备也能把图存成文件；中文标签靠上一层已装的 `fonts-noto-cjk`，用前选一下字体即可。
- **⚠️ 参数名比内容窄**：`INSTALL_PYTHON_DOCS` 是这一层只有 4 个文档库时留下的名字，**故意不改名**——已有 `.env` / `compose.yaml` 都设的是它，改名等于让老配置静默失效。正式表述里读作"**Python 库**"，别写"只装文档库"。
- **克制之处（已变）**：原先默认不加 `pandas` / `matplotlib` / `markitdown`，理由是"会让这层体积翻倍却换不来什么"；现在数值栈**默认装上了**，仍然不装的是 `scikit-learn`（在 numpy/scipy 之上再加 150MB 左右，技能里没有要训练的模型）和 `markitdown`（会拖进 magika + onnxruntime 做文件类型识别，为一个 LibreOffice/pandoc 已覆盖的转换器再翻一倍）——**真需要时都是一行**。→ **默认给通用能力，重且特化的留给需要的人。**

### 9.3 可选层开关

| 开关 | 内容 | 量级 |
|---|---|---|
| `INSTALL_OFFICE=1`（默认开） | `libreoffice-core/writer/calc/impress` + `pandoc` | **约 500MB 以上** |
| `INSTALL_PYTHON_DOCS=1`（默认开） | 见 9.1 第三层（文档库 + 数值栈 + 抓取/解析库） | 约 200–250MB |

### 9.4 LibreOffice 的两个取舍

- 装的是 **component 包**，不是 `libreoffice` 元包，全程 `--no-install-recommends`（元包会把 gtk3、Java、邮件合并拖进来，headless 转换不需要）；
- **LaTeX 故意不装** ⇒ `pandoc` 生成 PDF 需要另找引擎，用 `soffice --headless --convert-to pdf` 或 ghostscript。

- **故意不装**：`texlive-*`、`chromium`/`xvfb`、`build-essential`；
- ⚠️ 本机（Windows）无 Docker，**无法测量确切体积**，以上是量级。构建后 `docker image ls` 看实际值。

## 十、内置插件机制（三个插件；与「内置技能」是两套东西，别混）

> ⚠️ **别和第十一节搞混**：`skills/` 是**技能**（给 agent 的能力，SKILL.md），`plugins/` 是**插件**（改 UI / 加功能的 dsh bundle，package.json）。`skills/` 目前故意为空，`plugins/` 里有**三个**插件。
>
> ⚠️ **文章里必须突出 ①`dsh-file-download`**：agent 跑在服务器容器里，**交付物怎么拿出来全靠它**。这一环最容易被架构设计忘掉，也是"整套东西有没有意义"的分界。

| 事实 | 值 |
|---|---|
| 插件总数 | **三个**：`@local/dsh-file-download`、`@local/dsh-login-gate`、`dsh-minimax-h3` |
| 打包 | `plugins/` 下**每个目录**在构建期 COPY 到镜像 `/opt/dsh-plugins` |
| 构建期校验 | 逐项检查并**不符合即构建失败**：`package.json` 存在 → 有可解析的 `name` → 入口文件（`exports`/`main`）存在 → 声明了 `dsh.bundle.patch` 时该文件存在 |
| 启用时机 | **容器启动时自动启用**（不是构建期） |
| 为什么不能在建期启用 | profile 是 dsh **首次启动时才组合出来**的，构建期它不存在 |
| 启动脚本做的两件事 | ① 把包**软链**进 `$DSH_HOME/profiles/node_modules/`。这个链接**不会被 dsh 自己的投影清理删掉**：`removeLinkProjections` 只删指向 `<profile>/.dsh-module-fallback` 的链接<br>② 把 bundle 自带的 patch 层**追加进 `$DSH_HOME/cordis.patch.yml`**（home 级 patch）⇒ 这就是"首次启动就已生效"的原因 |
| 会不会被覆盖 | **只追加一次**，靠 `# bundled plugin: <name>` 标记去重 ⇒ 你之后改的选项**不会被后续启动覆盖** |
| 改选项的正确位置 | `data/dsh/cordis.patch.yml` 里对应插件的段落 → `docker compose restart dsh` |
| 运行时加插件（不重建） | 把宿主目录挂进容器，并把 `DSH_PLUGIN_ROOT` 指向它 |
| 凭据嗅探告警 | patch 里若匹配到 `^[[:space:]]*(password\|passwd\|secret\|token):`，启动日志会打四行警告 |

### 10.1 ⭐ `@local/dsh-file-download`：交付物出口（**文章重点**）

**痛点**：agent 在容器里生成文件，路径形如 `/workspaces/<项目>/out/report.pptx`。传统拿法都要跳出浏览器 + 知道准确路径：

```bash
docker compose cp dsh:/workspaces/<项目>/out/report.pptx ./
docker compose exec dsh ls -la /workspaces/<项目>/out/
ls -la ./workspaces/<项目>/out/     # 宿主挂载点
```

| 事实 | 值 |
|---|---|
| 功能 | 给文件加**下载按钮**，点击即走**浏览器自己的下载器**保存 |
| 按钮位置（四个插槽） | ① `deliverables.file.actions` — 交付文件卡片（`present` 工具）<br>② `deliverables.review.file.actions` — 完成轮次的改动文件复查页<br>③ `sidebar.right.tab.document.actions` — 右侧栏预览工具栏<br>④ `sidebar.right.tab.document.unpreviewable` — 右侧栏"无法预览"占位（**pptx 等二进制落在这里**）<br>前两个覆盖"本轮产出的文件"，后两个覆盖"任意工作区文件" |
| Host 路由 | **一条**带鉴权的 Fetch 路由：`GET\|HEAD /api/file.download` |
| 寻址方式 ①（坐标） | `?from=present&sessionId=<id>&seq=<事件序号>&index=<文件下标>`（或 `from=changes`）<br>**不传路径**；Host 侧回 Session 日志重新校验该坐标，从记录里取出路径 |
| 坐标寻址的安全含义 | **这条路由能下载的文件，绝不超出该 Session 自己记录过的文件。** 凭空构造 URL 无用 —— 这一点必须写进文章 |
| 寻址方式 ②（路径） | `?from=path&path=<绝对路径>`，与 Harness 自带的 `/api/file` 取图路由**共用同一套文件系统权限** |
| 大文件 | 走 `ctx.fs.readByteRange` **分窗流式**，默认 `chunkBytes: 1048576`（1 MiB），可配 4096–8388608 ⇒ **整份文件不进 Host 内存** |
| 单文件上限 | `maxBytes: 0`（默认）不设上限；设了则超出返回 `413` |
| 生命周期 | 注册 `AbortController`，插件卸载时**取消所有在飞的读取** |
| 响应头 | `Content-Disposition: attachment`（**ASCII 回退名 + `filename*=UTF-8''` 真实名**）、按扩展名推断的 `Content-Type`、`Content-Length`、`Cache-Control: private, no-store`、`X-Content-Type-Options: nosniff`、**`Content-Security-Policy: sandbox; default-src 'none'`** |
| 中文文件名 | **必须给两份文件名**：只有 `filename=` 时中文名在某些浏览器会乱码或丢扩展名 |
| 浏览器端流程 | 点击 → 先发 `HEAD` 预检 → 成功则造一个合成 `<a download>` 把 `GET` 交给下载器（**页面零缓冲**）；失败则图标转错误色并给提示 |
| 为什么"先 HEAD" | 让浏览器先判断成败，而不是"下到一半才报错"；体验上是"点了就有反应" |
| 拒绝码 | `400`（坐标非法 / 缺参 / 非绝对路径）、`403`（不是普通文件 / 权限或沙箱拒绝）、`404`（找不到）、`413`（超限）、`499`（被取消）、`500`（其它） |
| 为什么没有 `Config` schema | bundle 以 `link:` 方式装进 profile，**宿主半不能 import 任何裸包名**（`@deepseek-ai/schemastery` 只在 dsh 安装目录里，Node 按包的**真实位置**解析 import 会失败）⇒ 宿主半**零 import**，代价是没有 schema 校验与自动设置界面 |
| 验证状态 | Host 半 `route-check.mjs`（路径/交付/改动三种寻址、分窗重组、文件名与响应头、400/403/404/413 拒绝路径）+ 浏览器半 `client-check.mjs`（工厂装载、四个插槽、坐标改写、点击→HEAD→下载器接管）；**未验证：真实页面视觉表现与真实登录态下的端到端下载** |

## 十二、两处构建期自检（各自抓什么）

| 检查 | 抓什么 | 为什么非它不可 |
|---|---|---|
| `--dump-config`（空 home） | 每个插件 import 能解析 | 缺包在**构建期**失败，而不是留一个 crash-loop 的镜像 |
| **启动冒烟测试** | 镜像**能不能真启动一个 profile** | `--dump-config` 只组合配置、不 import 模块，**坏树它照样成功** |

冒烟测试的成功信号：**`timeout` 退出码 124**（时间到了服务还活着）。其他退出码都算"启动途中崩了"，并打印头 40 行日志。

冒烟测试还额外断言：`grep -q 'plugin tree failed to load'` 命中即失败；并从 `profiles/web` 目录里真跑 `require.resolve` 验证 `dsh-base` / `dsh-sandbox-local` / `node-addon-system/landlock-run` 都能解析。

## 十三、verify.sh

- **8 个阶段，9 条断言**（另有 1 种"读不到令牌"的直接失败路径）
- 链路：`DNS → TLS chain → Caddy → DSH browser-trust fence → launch token → session cookie → /api bridge → WebSocket upgrade`

| 请求 | 期望 |
|---|---|
| `GET /` 无 cookie | `401` |
| `GET /?token=<正确令牌>` | `303` + `Location: /` + `Set-Cookie` |
| `GET /` 带 cookie | `200` |
| `/api/*` 受信但无 cookie | `401` |
| 任意请求，Host 不受信 | `403` |
| WebSocket `/api/remote.mux` | `101` |

**三个值得写进文章的设计点**：

1. **期望码来自源码而不是猜测**——脚本头部标注 `authorizeIndex()` / `isTrustedApiRequest()`。
2. **负例必须在容器内直连 DSH，而且必须打 `/api`**：经过 Caddy 时错误 Host 会先被 Caddy 站点匹配回 404，测不到围栏；而打 `GET /` 也不行——它走 `authorizeIndex()`，**无论 Host 对不对都回 401**。
3. **主动声明 NOT covered**：客户端 DNS、到主机的网络路径、浏览器的证书点击。

## 十五、只在你启用了明文 :80 时才存在的东西

| 事实 | 说明 |
|---|---|
| 默认谁能连上 | `DSH_HTTP_ALLOWED_RANGES` 默认 `127.0.0.1/32 ::1/128` ⇒ 表外来源一律 `403` |
| 验证必须从客户端做 | 从服务器自己发起会经 docker 网桥，得到 403 **属正常** |
| 容器侧端口固定 80 | 宿主侧随便挑（如 `:81:80`），**但不要把宿主端口写进 `DSH_SITE_ADDRESS`**（那个变量同时构建 HTTPS 站点） |
| `DSH_TRUSTED_HOSTS` 仍需无端口 | 一个无端口条目覆盖 443 / 80 / 任意宿主端口 |
| `basic_auth` 在此通道上**没用** | 观察者能在同一口气里读到凭据和 cookie；它只对"从日志/Referer 泄露的 cookie"有帮助 |
| 两条路**不共享 cookie** | 各登录一次；但**共享同一份宿主设置文档**，一边改另一边能看到 |
| HSTS 只对域名生效 | 用 IP 访问时两条路可长期并存；一旦改用域名并成功 HTTPS，明文路会被浏览器升级掉一年 |
