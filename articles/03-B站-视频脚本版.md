### 【02:40–04:00】坑二：一句域名写错，永远 403

**画面**：浏览器 403 页面 → 源码片段（`isTrustedAuthority`）→ 正确写法对照

**口播**：

> 配好之后打开网页，403。
>
> 排查了半天，原因是我在"信任的域名"里很自然地写了 `域名:443`。
>
> **这个写法永远匹配不上。**
>
> 为什么？看它的实现：**不带端口的条目，只比主机名；带了端口的条目，要求完全一致。**
>
> 而浏览器的规矩是：访问默认端口的 HTTPS 时，请求头里的 Host **根本不带端口**。
>
> 所以正确写法是**光写域名，不要那个 443**。而且裸域名对任意端口都成立，以后你把站点挪到 8443 也不用改。
>
> 顺带说个反向的坑：这个值还必须是**裸的 authority**，你要是写成 `https://` 开头、或者带上路径，插件加载会直接报错。

**字幕要点**：`不带端口 → 只比主机名` / `带端口 → 必须完全一致` / `写 :443 = 永远 403`

**素材**：403 页面截图；源码高亮截图

**画面文字**：

```js
// 无端口条目 -> 只比 hostname；带端口条目 -> 比 host:port
return canonical === entryUrl.hostname
  ? entryUrl.hostname === hostUrl.hostname
  : entryUrl.host === hostUrl.host;
```

### 【04:00–05:20】坑三：它的登录 Cookie 故意不加密传输（这集最重要）

**画面**：浏览器开发者工具 → 找到那个 Cookie → 放大标注「没有 Secure 标志」→ 切到数据流示意动画

**口播**：

> 第三个坑让我后背发凉，也是这一集我最想让你记住的一条。
>
> 登录成功之后，它给浏览器发一个 Cookie。
>
> **这个 Cookie 故意没有加 "Secure" 这个标志**——也就是"只在加密连接上传输"。
>
> 为什么？因为它假设你走的是本机访问，`127.0.0.1`，本机通信本来就不出网卡。
>
> 但一旦你把它放到服务器上，这个假设就塌了。
>
> 所以结论非常硬：**同一个域名，绝对不能再开一个不加密的 HTTP 入口。**
>
> 第一次明文请求，这个 Cookie 就会在链路上裸奔。而它就是**唯一**的身份凭证——**拿到它，等于拿到服务器上那个 AI 的执行权。**
>
> 这就是我在配置里显式关掉 80 端口自动跳转、并且上了 HSTS 的原因。

**字幕要点**：`Cookie 没有 Secure` / `明文 = 凭证裸奔` / `它 = AI 的执行权`

**素材**：开发者工具录屏（Cookie 面板，注意**遮挡 Cookie 值**）；明文 vs 加密的动画对比

### 【05:20–06:40】坑四：重启，不等于把人踢下线

**画面**：一张对照表（做成表格图或逐行动画）

**口播**：

> 第四个是我理解错的。
>
> 我以为重启服务就能让所有登录失效，好把权限收回。**其实不能。**
>
> 它有两个东西：一个是**登录令牌**，每次启动重新随机生成；另一个是**登录 Cookie**，它的签名密钥存在硬盘上，默认 30 天有效。
>
> **重启换掉的只是令牌。已经在浏览器里登录过的人，照旧能进。**
>
> 真想把人全部踢下线，只能把硬盘上那个签名密钥删掉再重启。
>
> 还有一点更反直觉：**那个令牌自身是没有过期时间的。** 只要进程不重启，日志里那条链接就一直有效。
>
> **它等同于密码，而且明文躺在日志里。** 别截图发群里。

**字幕要点**：`重启 = 换令牌 ≠ 吊销登录` / `令牌没有过期时间`

**素材**：对照表动画；终端演示删密钥吊销（**token 全部打码**）

**表格图内容**：

| 你做了什么 | 登录令牌 | 已登录的浏览器 |
|---|---|---|
| 重启 / 重新构建 | 换新的 | 照旧能用 |
| 换端口或换域名 | 换新的 | 需要重新登录 |
| 删掉签名密钥后重启 | 换新的 | 全部失效 |
| 只清浏览器 Cookie | 不变 | 用日志里的令牌重新登录 |
| 超过 30 天 | 不变 | 过期 |

### 【13:50–15:10】文件下载插件：这一环才让整套东西有意义

> ⚠️ **这是改稿新增的重点段落。** 建议在这里**换一下节奏**：前面讲的是"怎么生成"，这一段讲"怎么拿到"。可以用一句反问做转场，效果最好。

**口播**：

> 好，现在东西都装齐了：能生成 PPT、Word、Excel、PDF，还能处理视频。
>
> **那问题来了——文件在容器里，我怎么拿到？**
>
> 你得先想清楚这件事：**这个助手跑在服务器上的 Docker 容器里。**
>
> 它生成的文件，路径长这样：`/workspaces/我的项目/out/报告.pptx`。
>

### 【15:10–16:10】它不是"随便开个下载接口"

**画面**：URL 结构图（坐标 vs 路径）→ 分块流式示意图 → 中文名响应头特写

**口播**：

> 不过这个插件我花心思最多的地方，不是"怎么让它能下"，而是"**怎么让它不能乱下**"。
>
> 因为一个下载接口，很容易变成服务器上的一个任意文件读取口子。
>
> 我的做法是：**交付卡片和复查页上的按钮，里面不存文件路径，只存一个坐标。**
>
> 坐标就是三个数：哪个会话、第几条记录、第几个文件。
>
> 服务器收到坐标之后，**回去翻会话日志重新查一遍**，从记录里取出真实路径。
>
> **这样一来，这个接口能下的文件，绝不超出这段会话自己记录过的东西。** 你手工构造一个链接，也是没用的。
>
> 另外三个细节我单独说一下：
>
> 第一，**大文件不会整个读进服务器内存。** 它是**分块往外送的**，默认每块 1 兆——所以交付一个 2G 的视频也不会把服务撑爆。
>
> 第二，**中文文件名不会乱码。** 响应头里文件名给了两份：一份 ASCII 的兜底名，一份真正的 UTF-8 名字。只写一份的话，中文名在某些浏览器上会变乱码甚至丢扩展名。
>
> 第三，**点击是"先探一下再下载"**：先发一个只查不传的请求确认文件在，成功了才把下载交给浏览器，**页面里一个字节都不缓存**。
>
> 所以你点下去的感觉是"立刻有反应"。失败就直接变红提示，而不是下到一半才报错。

**字幕要点**：`坐标寻址 ⇒ 只能下会话记录过的文件` / `分块流式，不进内存` / `中文名双份，不乱码`

**素材**：四类下载入口截图；下载成功与失败两种状态的录屏

### 【16:10–17:30】坑六：我为了"省事"踩的大坑

### 【17:30–18:50】坑七：一行代码救了设置页（最想分享的思路）

**画面**：设置页的报错 → 源码一行高亮 → 改成 `true` → 设置页正常

**口播**：

> 最后一个坑最技术，但我认为它是**整期视频里最值钱的思路**。
>
> 搬上去之后，"模型设置"页面打不开，提示一句话：设置只在这个浏览器里可用。
>
> 我去翻它的前端代码，找到了**一行写死的判断**：**如果页面不是从本机地址打开的，设置文档就只存在内存里。**
>
> 从域名访问，这个条件不成立，所以设置页废了。
>
> 关键来了：**我没有改它的代码，也没有重新编译整个项目。**
>
> 我只改了**那一行判断本身**。
>
> 为什么改这行就够？因为**有两个不同的地方都在用它**，改定义，等于同时修好了两个消费者。
>
> 而且这个改法是**写脚本自动做的**，脚本不认行号——**认的是整条表达式**。上游改代码把行号全挪了也没关系，只要这行没变，它就能找到。
>
> 万一哪天找不到，脚本不报个错就完，它会告诉你**该用哪条 grep 命令去找新写法**。

**字幕要点**：`改"定义" > 改"每个用到它的地方"` / `锚点用表达式，不用行号`

**素材**：设置页报错；源码高亮；**有现成素材 `img/model_setting.png`（改完后的设置→模型页，provider 与模型列表都是真的）**；脚本运行输出

**画面文字**：

```js
// 改前：从域名访问时，设置文档退化成"内存里的"
const persistence = ctx.remote.$host.isLoopback ? "host" : "memory";

// 改后：把那个"是不是本机"的判断直接置为 true
isLoopback: true
```

**⚠️ 诚实提示（口播要带一句）**：

> 这个改动放宽了一件事——**它让远程浏览器也能读写模型密钥**。
>
> 服务端的准入校验没有变松，但"谁能改密钥"的范围确实扩大了。这个取舍你得自己判断。

```
【仓库】https://github.com/zjwan461/dsh-docker
一个镜像、一个服务、一个对外入口（443）。clone 下来填个 API Key 就能起。

7 个坑的排查清单（按视频顺序）：

① --host 0.0.0.0 → 用 --patch 覆盖层改 webserver 行的 host
   注意 patch 是"替换"整行 config，同行的其它字段必须重述

② DSH_TRUSTED_HOSTS 必须是裸 authority，不能带 :443
   实现依据：无端口条目只比 hostname，带端口条目比 host:port

③ 会话 cookie 不带 Secure ⇒ 绝不给同一域名开明文入口
   同时上 HSTS；理由是它假设 loopback HTTP

④ 令牌每次启动重新随机、不落盘、无过期时间
   cookie 签名密钥在 $DSH_HOME/.credentials.yaml，默认 30 天
   吊销所有人：删掉那个密钥文件再重启

⑤ 内核需 ≥ 5.13；镜像故意不装 bubblewrap，让容器落到 Landlock
   验证：GUI 里让 agent 写工作区外的路径，应看到
   [sandbox: file access denied under workspace-write mode]
   边界：只限制写，读和网络不受限

⑥ profiles/node_modules 投影不完整 ⇒ 遮蔽安装树
   而 profile 的 package.json 没有依赖 ⇒ 永远不会重建
   修法：rm -rf data/dsh/profiles/node_modules && docker compose restart dsh
   先备份！容器里没有 npm registry

⑦ isLoopback 那一行改 true（构建期以 root 应用）
   脚本锚点用整条表达式，不用行号；写盘前用语法校验兜底
   代价：远端浏览器可读写 provider 凭据

镜像里预装了什么（这半期同样重要）：
   Python：python-pptx / python-docx / openpyxl / Pillow
     → 让 agent 能"交付一份文件"，而不是只给一段文字
     → python-pptx + Pillow 正是生成 PPT 的那两个库
   媒体：ffmpeg（转码/抽帧/缩略图）sox（音频裁剪拼接）
        imagemagick（convert/identify/montage）exiftool（EXIF 读写）
   PDF：poppler-utils / qpdf / ghostscript
   文档：LibreOffice（组件包，不是元包）+ pandoc
   字体：fonts-noto-cjk  ← 没它中文文档转 PDF 就是满屏方框
   三个自检命令（缺哪个就去查 .env 的 INSTALL_* 开关并重建）：
     docker compose exec dsh ffmpeg -version
     docker compose exec dsh python3 -c "import pptx, docx, openpyxl, PIL; print('ok')"
     docker compose exec dsh fc-list | grep -ci CJK     # 应为正数

内置插件（三个）：
   plugins/ 下每个目录 → 构建期打进 /opt/dsh-plugins → 启动期自动启用
   启用必须在启动期：profile 是 dsh 首次启动才组合出来的
   启动脚本做两件事：软链进 profiles/node_modules + patch 追加进
     $DSH_HOME/cordis.patch.yml（只追加一次，之后你改的选项不会被覆盖）

   ① @local/dsh-file-download ← 最关键的一个
      为什么必须有它：agent 跑在服务器容器里，交付物在
        /workspaces/<项目>/out/xxx.pptx
      传统拿法（都要跳出浏览器 + 知道准确路径）：
        docker compose cp dsh:/workspaces/.../xxx.pptx ./
        docker compose exec dsh ls -la /workspaces/...
        在宿主挂载点 ./workspaces/... 里翻
      它的做法：给文件加下载按钮，交给浏览器自己的下载器
      按钮出现在四个位置：
        deliverables.file.actions              交付文件卡片
        deliverables.review.file.actions       改动文件复查页
        sidebar.right.tab.document.actions     预览工具栏
        sidebar.right.tab.document.unpreviewable  无法预览占位（pptx 落这）
      安全性：卡片按钮只带"坐标"（sessionId / seq / index），不带路径；
        Host 侧拿坐标回 Session 日志重新查一遍 ⇒ 能下的绝不超出
        该会话记录过的文件。凭空构造 URL 没用。
      大文件：走 ctx.fs.readByteRange 分块流式，默认 1 MiB/块，不进内存
      中文名：Content-Disposition 给两份（ASCII 回退 + filename*=UTF-8''）
        → 只写一份的话中文名会乱码甚至丢扩展名
      点击流程：先 HEAD 预检 → 成功才把 GET 交给浏览器下载器
        （页面零缓冲，"点了就有反应"）
      可调（写进 cordis.patch.yml）：
        chunkBytes: 1048576    # 4096–8388608
        maxBytes: 0            # 0 = 不限，超出回 413

   ② @local/dsh-login-gate
      ⚠️ 它不是认证，校验在浏览器里做、凭据随页面下发
      ⚠️ 默认凭据公开（admin / dsh-admin），改了才安全
      改选项：编辑 data/dsh/cordis.patch.yml → docker compose restart dsh

   ③ dsh-minimax-h3（视频工作室，重插件）
```

## 七、专栏图文版 · 精简改写方案

如果你还想在 B站发一篇专栏配合视频（或视频被限流时的备份），按下面的方式改写：

**必须遵守**

1. **不要贴代码块** —— 会变成没高亮的纯文本。把代码截图后当图片插入。
2. **不要用表格** —— 不支持。把对照表做成图片。
3. **不要指望 Markdown 语法** —— 只保留标题、段落、加粗、斜体、列表。
4. **图片要手动上传**，粘贴不进来。

**建议结构（2500 字左右）**

```
标题：我写了一个真正能在 Docker 里跑起来的 AI 助手部署模板（文字版）

开头（150字）：一句话说清背景 + 结果

主体：10 个小标题，每个 150–250 字
  前 7 个 = 7 个坑，每个讲清三件事：
    现象（我看到了什么）
    原因（为什么它要这么做）
    解法（我改了什么）
  后 3 个 = 让它"有用"的那一半：
    · 镜像里预装了什么（Python 文档库 / ffmpeg / PDF / 中文字体）
    · **文件下载插件：交付物怎么从容器里拿出来（小标题里直接点名）**
    · 内置插件机制，以及另外两个插件（门禁 / 视频工作室）
  ← 这样即使不看视频也能读懂，但细节留在视频里

配图（10–12 张）：
  · 架构图
  · 403 报错页
  · Cookie 没有 Secure 的截图
  · 令牌/Cookie 对照表（做成图）
  · 沙箱拦截日志
  · 中文方框 vs 正常 的对比图   ← 最值得放的一张
  · 三类预装能力的清单图
  · **下载按钮出现的四个位置（截图标注）**  ← 专栏里最该放的技术图
  · 登录门禁界面截图

  · isLoopback 那一行代码

结尾（100字）：引导到视频 + 提问
```

> ⚠️ 专栏有最低字数要求，上面这个结构（约 2500 字）是安全的。
