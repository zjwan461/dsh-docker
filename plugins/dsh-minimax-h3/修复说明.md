### 本次新增修掉的 5 处陈旧说法（上一轮遗漏）

上一轮的补丁只改了 4 处（3 处 `workflows.js` 注释 + 1 处 skill 正文），但**面向模型和用户的字符串**里还留着 6 处，模型读到 description 就会照错的规则去算帧数：

| 文件 | 位置 | 原句 → 现句 |
|---|---|---|
| `lib/tools.js` | `h3_generate` 的 `description` | `legal frame counts (4n+1 at 24 fps)` → `legal frame counts (5 mod 17: 5, 22, 39, …, 124, 158, 243, 362, 481)` |
| `lib/tools.js` | `frames` 参数说明 | `nearest legal 4n+1 value ≥ your input` → `nearest legal frame count ≡ 5 (mod 17) ≥ your input` |
| `README.md` | 「时长：会比你填的长一点」 | `H3 只接受 **4n+1** 帧` → `≡ 5 (mod 17) 帧…，**不是 4n+1**` |
| `README.md` | 自测清单说明 | `官方 4n+1 规则的取值表` → `官方 ≡ 5 (mod 17) 规则的取值表` |
| `scripts/smoke.mjs` | 小节标题 | `duration → frames (the official 4n+1 rule)` → `(the official ≡ 5 mod 17 rule)` |
| `lib/skill.js` | 帧数正文（上一轮已改） | 同上 |

结论：**"注释已改"不等于"说清楚了"**。凡是模型/用户会读到的字符串（工具 description、参数说明、README、自测标题）都要一起查。

## 四、怎么安装（本包**没有**替你安装）

三种方式，选一种。⚠️ **插件代码在 harness 启动时加载，装完必须重启 DSH 才生效**（当前进程里跑的还是旧代码）。

**方式 A — 用补丁打（推荐给 root 部署 / 上游提交）**

```bash
# 对只读的 /opt 原件打（需要 root；本会话没有也没有尝试执行）
for p in patches/*.patch; do
  patch -p1 -d /opt/dsh-plugins/dsh-minimax-h3 < "$p"
done
# 若 profile 里是副本而非软链，需要同步；若是软链则 /opt 改完即生效
```

也可以用幂等脚本：

```bash
python3 patches/apply_h3_fixes.py --target /data/dsh/profiles/node_modules/dsh-minimax-h3
```

**方式 B — 整体替换 profile 里的插件目录**

```bash
rm -rf /data/dsh/profiles/node_modules/dsh-minimax-h3
cp -a /workspaces/video/out/dsh-minimax-h3-fixed /data/dsh/profiles/node_modules/dsh-minimax-h3
```

**方式 C — 只回退软链，再改 /opt**（见 `插件修复说明_dsh-minimax-h3.md` §1.2 的两条路线）

**重启后人工复验**（这 3 条是本轮唯一没能在重启前验证的，因为它依赖 harness 真的按契约调 `render`）：

1. `h3_assets action: "ffmpeg"` → 应返回真实 FFmpeg 探测报告，而不是 `{"action":"ffmpeg"}`；
2. `h3_runs action: "inventory"` → 模型清单，且 `h3_generate` 不再因模型文件名失败（跑一条 124 帧 turbo i2v）；
3. `h3_project save` → 返回的 id 应是真实落盘 id，而不是传入的 id。
