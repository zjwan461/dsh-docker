# 交付规范与自动质检

片子做完不等于能发。这一份是"导出前最后一小时"的清单，配 `scripts/qa.py` 做机器能查的部分。

---

## 1. 画幅与分辨率

| 平台 | 画幅 | 交付尺寸 | 帧率 |
|---|---|---|---|
| 抖音 / 快手 / 视频号 | 9:16 | 1080×1920 | 24 或 30 |
| B站 / YouTube 横屏 | 16:9 | 1920×1080 | 24 或 30 |
| 小红书 | 3:4 或 9:16 | 1080×1440 / 1080×1920 | 24 或 30 |
| 封面（B站） | **16:10** | 1920×1200 | — |

H3 生成用 0.4–1.0MP，交付前统一放大到目标尺寸；**不要用生成尺寸直接发**。

---

## 2. 竖屏安全区

以 1080×1920 为基准（不同平台 UI 会变，**发布前用平台预览再核一次**）：

| 区域 | 建议 |
|---|---|
| 顶部 | 留 120–160px，不放标题 |
| 底部 | 留 300–400px，不放关键信息（字幕、CTA） |
| 右侧 | 留 100–140px，避开点赞/评论按钮 |
| 字幕基线 | 距底 380–420px |
| 主字幕字号 | 高度的 3.5–4.5%（约 68–86px） |

**关键信息（人脸、产品、字卡）永远放在中间 60% 的安全框里。**

---

## 3. 字幕

> **先读 `subtitles.md`。** H3 自己会渲染字幕（画进像素），所以"要不要叠"不是默认动作。
> 烧之前必须 `qa.py <clip> --textcheck` 看底部横条，确认素材干净。

- 一行 **≤16 个汉字**，最多两行；超过就拆句，不要缩字号。
- 硬字幕优先（兼容性最好）；要可开关再做软字幕。
- 描边 2–3px + 轻微阴影，纯白字在亮背景上会糊。
- 数字用阿拉伯数字，**逐字对配音**；"28%" 不要写成 "百分之二十八" 的字幕而配音念的是数字。
- 字幕不能压脸：先在时间线上标出人脸位置，再排字幕。

ASS 规范：

```text
PlayResX: 1080
PlayResY: 1920
Style: Default,思源黑体,72,&H00FFFFFF,&H000000FF,&H00000000,&H80000000,0,0,0,0,100,100,0,0,1,3,0,2,80,80,400,1
```

`MarginV=400` 是竖屏的底盘线；横屏用 60–80。**一个 filtergraph 只串一次 `subtitles=`**。

## 4. 响度与音轨

| 项 | 目标 |
|---|---|
| 集成响度 | **−16 LUFS**（抖音/B站/YouTube 通用） |
| 真峰值 | ≤ **−1.5 dBTP** |
| 对白/旁白 | −16 LUFS 左右，环境底低 4–6dB |
| 声道 | 立体声，48kHz |

**H3 原生音轨经常接近 0dB**（实测峰值 −0.3 / 0.0 / −1.2 dB），直接发会爆。交付前必做：

```bash
ffmpeg -i in.mp4 -af "loudnorm=I=-16:TP=-1.5:LRA=11" -c:v copy out.mp4
```

两遍 `loudnorm`（先测后施加，`linear=true`）更稳；单遍会重新揉动态。

## 5. 封面

| 用途 | 尺寸 | 注意 |
|---|---|---|
| 抖音竖屏 | 1080×1920 | 主体占中间，字占上 1/3 |
| B站 | **1920×1200（16:10）** | 用 16:9 会被裁边 |
| YouTube | 1920×1080 | 字不贴边 |
| 小红书 | 1080×1440 | 3:4 |

封面字**不超过 12 个字**，一行为主；生僻人名不上封面（观众不认识），留给简介。

## 6. 合规与标注

- 发布时标注 **AI 生成**（平台要求 + 观众信任）。
- 音乐/音效必须有版权；H3 生成的原生音轨可用，但 BGM 不要用来路不明的。
- 真人肖像、明星脸、品牌 logo 不要生成。
- 科普内容：每个数字有出处；健康类不给治疗建议；引用写"研究发现/相关"。
- H3 权重是社区许可（排除美/欧/英/韩），商用前看清条款。

## 7. 自动质检 `scripts/qa.py`

```bash
python qa.py EP01/out/final.mp4
python qa.py clips/*.mp4 --json qa.json
```

每条片子报：

| 项 | 说明 |
|---|---|
| duration / fps / frames | 和分镜表对不对得上 |
| resolution | 是否目标画幅 |
| audio | 有无音轨、采样率、声道 |
| loudness | 集成响度（LUFS）、真峰值 |
| freeze | 冻结段（`freezedetect`），>1s 报警 |
| black | 黑场段（`blackdetect`），意外黑场报警 |
| cuts | 场景切换次数（`scene>0.3`），和分镜镜数对照 |
| warnings | 响度超标、峰值过载、无音轨、冻结过长、分辨率不符 |

它只报事实，不判断好不好看。**"这段能不能用"仍然要人眼抽 5 帧。**

## 9. 合片三坑

- **filter 级 concat 要求每段分辨率一致**：只要有一镜是别的尺寸（例如静帧做的慢推），每路都要先 `scale=1080:1920:flags=lanczos,setsar=1` 再进 concat，否则报 `Input link in0:v0 parameters (size ...) do not match`。
- **静帧做的慢推要配静音轨**：`-f lavfi -i anullsrc=r=48000:cl=mono`，否则 concat 的 `[i:a]` 匹配不到流（`Stream specifier ':a' ... matches no streams`）。
- **人物小、灯多、易崩的远景，用静帧 + `zoompan` 代替 i2v**：
  `zoompan=z='if(lte(on,1),1.10,max(1.0,zoom-0.0010))':x='iw/2-(iw/zoom/2)':y='ih/2-(ih/zoom/2)':d=107:s=1080x1920:fps=24`
  零伪影、几秒钟出片，比 4 步 i2v 还稳。
