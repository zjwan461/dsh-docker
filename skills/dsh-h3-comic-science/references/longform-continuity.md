# 长片连续性

H3 一次只有 4–15 秒。任何超过 15 秒的片子，都是**一串接缝**。这一份解决"第 3、4 段开始崩"。

文中的数字来自一批跑过几千条片段的实测记录（nextsycl 的 H3 工程笔记、场景边界测试、ComfyUI Continuity Studio 的说明），凡是引用都标了来源性质；**没标数字的是工程经验**。

---

## 1. 先搞清楚：接缝为什么会崩

### 1.1 单张关键帧只钉住"姿态"，钉不住"速度"

实测六组接缝：**切点那一帧两侧能对上 35.6 dB PSNR，但 1/2/4/8/12 帧之后掉到 32.0 / 29.9 / 28.2 / 24.4 / 22.8 dB。**

翻译成人话：**接上的那一帧是像的，动起来立刻分岔**。你看截图觉得"接上了"，一播放就"跳一下"。

所以：**"末帧接力"能骗过暂停键，骗不过播放键。**

### 1.2 漂移会累积

每个"解码→再编码"的来回，锚点暗约 **1 个 luma 单位**。实测一条 18 段的链，末段比首段**暗 19%**。

不是"某一段坏了"，是**每一段都坏一点，攒起来**。

### 1.3 景别会自己爬

写 "pushes in slightly"，连挂六段之后变成大特写。

模型把"稍微推近"当成每段的独立指令，累积效应没人管。

---

## 1.5 实测：接缝是好的，漂移藏在接缝之间

**设置**：同一张锚点帧（会议室三人），`i2v` 4 秒 @0.4MP、turbo 8 步，四段用**完全相同的提示词**——
"静态机位、保持构图与曝光、光线从首帧到末帧保持不变"。
一条链：锚点 → A → B → C（每段首帧 = 上一段末帧）；一条 Hub：锚点 → D（与 A 同一输入、不同 seed）。

### 亮度（YAVG）

| 环节 | 首帧亮度 | 相对锚点 |
|---|---|---|
| 锚点 | 83.21 | — |
| 链第 1 跳 A | 80.93 | −2.28 |
| 链第 2 跳 B | 78.76 | −4.44 |
| 链第 3 跳 C | **76.02** | **−7.19（−8.6%）** |
| **Hub D（同样从锚点出发）** | 80.68 | **−2.53（只有 1 跳的量）** |

### 相似度（缩到 320×320 比 PSNR）

| 对比 | PSNR |
|---|---|
| A 起帧 vs 锚点 | 33.5 dB |
| **链 A 末 → B 首** | **33.8 dB** |
| **链 B 末 → C 首** | **34.2 dB** |
| Hub D 起帧 vs 锚点 | 33.3 dB |
| **链第 3 跳 vs 锚点** | **13.1 dB** |

### 三条结论

1. **每一个接缝单独测都是好的（33.8 / 34.2 dB）**——这正是"看片段觉得接上了"的原因。
2. **三跳之后整体偏到 13.1 dB**——已经不是同一张画面了。**漂移不在接缝上，在接缝与接缝之间。**
3. **Hub 永远停在"1 跳"的水平（33.3 dB / −2.5 luma）**，因为每次都从锚点重新出发，误差不叠加。

### 一条意外发现：段内会自己回弹

- C 段：起 76.02 → 末 **80.48**（段内涨 4.5）
- D 段：起 80.68 → 末 **76.86**（段内跌 3.8）

**段内波动（±4）比每跳损失（−2.2）还大。** 所以"全片链完再统一拉亮"不可靠——必须在**每一段**都对齐，或者干脆用 Hub。

> 这些数字是 4 秒 / 0.4MP / 8 步打样档跑出来的。定稿档（0.7–1.0MP、20–25 步）绝对值会变，但"每跳损失、接缝好而整体漂"的规律方向不变。

## 2. 帧规划：按帧算，不按秒算

H3 的帧数是 **17k+5**（5, 22, 39, 56, …, 243, 260, 277, 294, 311, 328, 345, 362）。

请求 10 秒 → round(240) → 吸附到 243 帧 = **10.125 秒**。
请求 5 秒 → 124 帧 = 5.167 秒。

| 你要 | 帧数 | 实际秒 |
|---|---|---|
| 4s | 107 | 4.458 |
| 5s | 124 | 5.167 |
| 6s | 158 | 6.583 |
| 8s | 192 | 8.000 |
| 10s | 243 | 10.125 |
| 12s | 294 | 12.250 |
| 15s | 362 | 15.083 |

**排时间线一律用"实际秒"，不要用你填的整数秒。** 三段 5 秒接起来是 15.50 秒，不是 15 秒。

### 2.1 幕长规划公式

```
第 1 段帧数 f1 = 17k+5 里 >= (beat × 24) 的最小值
后续每段    fi = f1（幕长不变）
成片总帧数  Σ fi
```

按 10 秒一幕、8 段算：243 × 8 = 1944 帧 = **81 秒**。
写剧本时按 81 秒排，不要按 80 秒排——差出来的 1 秒会让最后一句台词被截。

## 3. 四种接法

| 接法 | 继承什么 | 本插件能不能做 | 适合 |
|---|---|---|---|
| **续接** | 动作 + 构图 | ✅ i2v（末帧当首帧） | 一个动作没拍完 |
| **硬切** | 什么都不继承 | ✅ 直接 concat | 正反打、换空间 |
| **新场** | 只继承"看"（画风/光） | ✅ t2v + 风格参考 | 换地点、换时间 |
| **桥接** | 两端都不动 | ✅ 单独生成 2–4 秒过渡镜 | 两端接不上 |

### 3.1 续接：连 PNG，不要连 latent

**这是硬规则。** latent 切片不等于"重新编码一张图"（VAE 在时间维上压缩，尺度也不同），拿 latent 接会让下一段**莫名变亮/变暗，还带假纹理**。

本插件走的就是"末帧存成 PNG → 当下一段首帧"，方向是对的。

### 3.2 续接的三个细节

1. **末帧从最后 0.5 秒里挑最干净的一帧**，不要死取最后一帧（可能是运动模糊、闭眼、穿模）。
2. **上一段结尾要收束动作**，不要停在高速运动的中间——高速尾帧接出去，下一段开头会抖。
3. **下一段不要再写"新构图"**，只写从这张图之后发生什么。重写构图 = 和首帧打架。

### 3.3 硬切就按硬切拼

实测结论：**硬切什么都不继承**。所以：

- 直接 `concat`，**不要加交叉淡化**——加了反而像失误。
- 音频各自按画面长度裁齐（H3 音轨会比画面长一点点），头尾加 **6ms** 淡化防爆音。
- 用 `scripts/seam.py` 先量一下：PSNR < 25dB 就是真硬切，不用修。

### 3.4 桥接镜

桥接镜只干一件事：把 A 的结尾变成 B 的开头。2–4 秒，不承载剧情。

```text
[Shot 1] ... the camera pushes into the rain on the window until the glass fills the frame; the reflection smears into a white glow.
```

好处：**A/B 都不用重渲**。桥接砸了重做桥接就行。

## 4. Hub 还是 Chain：这是长片最重要的一个决策

### 4.1 链式（Chain）

```
A → B(从A末帧起) → C(从B末帧起) → D ...
```

- 优点：动作连续，一镜到底的感觉。
- 缺点：**误差累积**。亮度每段掉一点，构图每段爬一点，第 4 段开始明显。

### 4.2 轮毂式（Hub）

```
        ┌→ B（起于 A 末帧，收于 A 末帧）
A ──────┼→ C（起于 A 末帧，收于 A 末帧）
        └→ D（起于 A 末帧，收于 A 末帧）
```

每段都从**同一个锚点**出发，也**回到同一个锚点**。

- 优点：**误差不累积**。实测"起止都钉在同一帧"能到 33.8 dB，和开场一样准。
- 代价：**每段必须回到开场那个姿态和构图**。这不适合"一路往前走"的戏，适合**同一空间里的对话/对峙/群戏**。

### 4.3 怎么选

| 戏的类型 | 选 |
|---|---|
| 对话、审问、对峙、议事 | **Hub**（同一空间、反复切） |
| 追逐、打斗、一镜到底 | Chain（必须往前推） |
| 混合 | 场次内 Hub，场次间硬切 |

**本插件做 Hub 的方式**：每段都用同一张 PNG 当 i2v 首帧，提示词里写"结束时回到起始姿态与构图"。

> 注意：本插件的 i2v **只有首帧**，没有尾帧槽。所以 Hub 的"收于同一点"只能靠提示词要求，**不如官方 FL2VA 硬**。
> 能接受就用；要严格就上 `comfyui-h3-continuity-studio` 或官方 API。

## 5. 亮度漂移：唯一必做的后期修正

每个来回暗约 1 luma。18 段能暗 19%，肉眼看就是"越到后面越脏"。

### 5.1 检测

```bash
ffmpeg -hide_banner -nostats -i clip.mp4 -vf signalstats,metadata=print -f null - 2>&1 | grep YAVG
```

或者直接跑 `scripts/seam.py A.mp4 B.mp4`，它会报两段的亮度差；**差 > 8 就会在切点闪一下**。

### 5.2 修正

以**第 1 段的末帧**为基准，把每段的增益拉回去（只做增益，不要重新调色）：

```bash
# 目标亮度取第一段末帧的 YAVG，比如 96
ffmpeg -i clip.mp4 -vf "eq=brightness=0.04:contrast=1.0" -c:v libx264 -crf 18 out.mp4
```

经验：增益控制在 **0.75–1.35** 之间，超出说明不是漂移，是光影本来不同，别硬拉。

### 5.3 根本办法

**Hub** 而不是长链——不累积，就不用修。

## 6. 构图漂移（framing creep）

"pushes in slightly" 连挂六段 = 大特写。

**做法：**

1. 每段提示词**正面锁定景别**，不要写"稍微"：
   ```text
   That exact shot size and camera position hold from the first frame to the last.
   ```
2. 全片**只允许一种主运镜**（推 / 拉 / 摇 / 跟，选一个），不要每段换。
3. **两台"摄影机"剪在一起**（一个手持一个固定）观众会觉得抖，全片统一。

## 7. 声音连续性

### 7.1 环境声必须跨镜相接

每段各自生成环境声 → 每个切点"呼"一声换空间，而且**在单段里完全看不出来**。

做法：同一场次内，`overall_soundscape` 写**同一句**并声明延续：

```text
The same courtyard at dusk: low wind through the eaves, one distant bird, dry rustle of silk.
This ambience continues unchanged from the previous shot and must not restart or change.
```

换场次才变。

### 7.2 环境声不要写太满

实测：天气、交通、电气底噪这类"铺底"写多了，回来是**嘶嘶声**，甚至把底噪渲染成音乐。

**只写画面里真有东西发出的声音**（脚步、布料、开关、水）。

### 7.3 音量：按响度统一，不要按峰值

- 逐条按峰值归一化 → 增益能到 1.6–5.2 倍，**每个切点环境底都鼓一下**。
- 正确：**按 LUFS 统一**（对话类片子 −18 到 −16 LUFS），最后加限幅。
- 片尾淡出 **1.5 秒**。

跑 `scripts/qa.py` 会直接报出集成响度和真峰值。

## 8. 剧集圣经（系列化的地基）

开工前落一份 `bible.md`，之后**每集只改剧情，不改这三块**：

```markdown
## 角色
- CHAR-01 阿杰｜25 岁中国男生，偏瘦，短寸头，黑方框眼镜，灰色连帽卫衣，黑色运动短裤，白色运动鞋
  连续性锁：`short buzz cut, black square-framed glasses, grey hoodie`
  声音：年轻男声，快，咋呼（S1）
- CHAR-02 啵啵｜人形女外星人，珍珠灰皮肤，光头，琥珀色大眼，额头菱形发光印记，深藏青长外套
  连续性锁：`pearl-grey skin, glowing diamond mark, deep navy coat with light-blue trim`
  声音：冷静女声，慢，带损（S2）

## 场景
- LOC-01 出租屋｜单人床靠左墙，电脑桌靠窗，黑色台灯，墙上手写计划表
  轴线：门在画左，窗在画右
- LOC-02 胃酸工厂｜不锈钢厂房，中央传送带，尽头酸池，墙上 pH 表

## 状态机
- PROP-01 计划表：第 1 集"贴上去" → 第 9 集"撕掉换新的"
- INJURY-01 左手背烫伤：第 3 集出现 → 第 5 集结痂 → 之后不再提

## 声音
- 同场次用同一句环境底，跨镜声明延续
- 全片 LUFS 目标 −16，片尾淡出 1.5s
```

### 8.1 身份 vs 变体

- **身份**：这个人是谁，跨集不变（脸、体型、标志物）。
- **变体**：身份不变，但服装/伤势/时段/天气/持物变了。
- **连续性锁**：只锁**不随剧情改变、且观众看得出不一致**的事实。

"换了件外套"是变体，不是新角色；"眼镜换了方框变圆框"是穿帮。

### 8.2 锁短语必须逐字照抄

同义词对人类相近，**对模型意味着重新采样身份**。
"grey hoodie" → "gray sweatshirt" 就可能长出另一件衣服。

## 9. 逐镜连续性四字段

每条镜头都要能回答，并且和相邻镜对上：

| 字段 | 说明 |
|---|---|
| 位置 | 站/坐/跪，画面左中右，离对手多远 |
| 目光 | 看谁、看哪、是否看镜头 |
| 双手 | 在做什么、抓着什么 |
| 持物 | 手里/身上有什么，数量 |

提示词里显式写 `Start state:` 与 `End state:`。**不许用"保持连续"糊过去**——位置对不上，观众立刻出戏，这是"像 PPT"最主要的来源。

## 10. 漂移诊断表

| 症状 | 根因 | 修法 |
|---|---|---|
| 第 3/4 段脸变了 | 只靠文字锁，参考图没每段都挂 | 每段都挂同一组 r2v 参考图；近景加面部板 |
| 越到后面越暗/越脏 | 解码编码来回累积（−1 luma/段） | 用第一段末帧做亮度基准拉回来；或改 Hub |
| 房间越拍越宽/越窄 | 景别漂移 | 正面写死 `that exact shot size holds` |
| 衣服颜色渐变 | 每段换了同义词 | 用连续性锁短语，逐字照抄 |
| 动作接不上 | 上一段没给终点 | 写 End state / Start state |
| 切点"呼"一下 | 环境声每段重启 | 同场次同一句 + 声明延续 |
| 切点闪一下 | 亮度跳变 >8 | `seam.py` 量出来，用 eq 对齐 |
| 拼接倒回一下 | 重叠没裁（复读了上一段尾巴） | `seam.py --frames 20` 看 best_offset，裁掉 |
| 越拼越"平" | 段间全是硬切中景 | 加桥接/甩镜/景别跳级 |
| 主体慢慢飘出画外 | turbo 4 步的 r2v 保真不足 | 定稿关 turbo，或降到 8 步以上 |

## 11. 一集怎么拼（3 分钟）

| 段 | 时长 | 接法 | 备注 |
|---|---|---|---|
| 冷开场 | 5s | 新场 | 黑屏/空镜 + 旁白 |
| 钩子 | 15s | 硬切 | 第一个实拍镜 + 标题卡 |
| 主体 | 8 × 15s | 段内 Hub、段间硬切 | 每段一个信息点 |
| 反转 | 15s | 硬切 + 声音桥 | 上一段话音压过切点 |
| 收尾 | 10s | 续接/桥接 | 定格 + 一句判断 |
| 片尾卡 | 3s | 硬切 | 黑场 + CTA |

**每 3–4 段换一次节奏**（大广角 → 特写 → 中景），否则三分钟"一个味"。

## 12. 本插件的能力边界（诚实清单）

| 官方/第三方能力 | 本插件 | 影响 |
|---|---|---|
| 首帧（I2VA） | ✅ `mode: "i2v"` + 1 张 ref | 够用 |
| 尾帧（FL2VA） | ❌ | Hub 的"收于同一点"只能靠提示词，不硬 |
| 参考图 1–9 张（R2V） | ✅ `mode: "r2v"` | 跨镜锁人的主力 |
| 参考视频 / 参考音频 | ❌ | **锁不住音色**，跨段声线靠"音色形容词 + 抽卡" |
| 移动引导帧（22 帧 guide） | ❌ | 接缝只能靠"末帧 PNG + 动作接动作"，抖动比官方方案大 |
| 音频锚点（first_audio） | ❌ | 跨段环境声连续性差，只能后期铺一条统一底噪 |
| 亮度对齐（exposure_ref） | ❌ | 用 ffmpeg `eq` 手动修 |

**结论：本插件适合"场次内 Hub + 场次间硬切"的结构；不适合做长链一镜到底。**
要做长链，用 `comfyui-h3-continuity-studio`（喂前段五帧 latent 记忆）或官方 API 的 guide/first_audio。
