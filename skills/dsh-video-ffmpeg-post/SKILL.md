# FFmpeg 后期：能交付的片子

## 1. 合片

```
ffmpeg -y -f concat -safe 0 -i list.txt -c copy -movflags +faststart film_raw.mp4
```

- `list.txt` 每行 `file '/absolute/path/clip.mp4'`。同源同参数（同分辨率/帧率/编码）用 `-c copy`，秒级无损。
- **逐镜时长以 `ffprobe` 的实测值为准**排时间线；容器时长与内容时长会差几十毫秒，
  累到十几镜就是零点几秒的漂移（本轮 100.494 vs 100.461）。
- 字幕/字幕卡的入点全部**从实测偏移算**，不要手写时间码。

### ⚠️ 时间基不一致时，concat 解复用器会**悄悄重复帧**

`-f concat -safe 0 -i list.txt` 是拼接最省事的写法，但它**沿用了各段自己的时间基**。
只要有一段的 timebase 跟别的不一样（典型的：用 lavfi `color=` 生成的纯黑卡，timebase 1/24；
H3 出的是 1/12288），后面的帧就会被 `fps` 滤镜补出来，**总时长凭空变长而且没人报错**：

> 真实案例：16 段本该 83.4 秒，出来 **108.9 秒**——多出来的 25 秒全是重复帧。
> 而每一段的单独 `ffprobe` 都是对的（5.167s），所以查错时看不出问题。

判断：`ffprobe` 各段时长之和 ≈ 83.6，但成片 108.9 → 就是这一条。

**解法：用 filter 级 concat**，时间戳由滤镜重算，绝对确定：

```
ffmpeg -i a.mp4 -i b.mp4 -i c.mp4 \
  -filter_complex "[0:v][0:a][1:v][1:a][2:v][2:a]concat=n=3:v=1:a=1[cv][ca];[cv]fps=24,…[v]" \
  -map "[v]" -map "[ca]" out.mp4
```

段数多（十几段）也没问题，一次调用就够。顺带说：filter concat 对**分辨率/帧率不一致**的输入
也比解复用器宽容。

### ⚠️ 音轨绝对不能跟着 `-c copy` 一起拼（本项目最贵的一个坑）

`-c copy` 把多段 **AAC** 裸流拼进一个 MP4，会产出**无法解码**的音轨：

```
[aac] Number of scalefactor bands in group (51) exceeds limit (49).
Error while decoding stream #0:1: Invalid data found when processing input
```

**症状极具欺骗性**：画面完全正常，`ffprobe` 也报得出时长，但解码器一帧都出不来。
混音时这一路等于**静音**，于是表现为"**画内口播全部消失，而后来另加的旁白还在**"——
非常像"混音把口播压掉了"，我因此在混音参数上白折腾了一轮。

正确做法：**音轨单独走 PCM**——逐段解码成 wav、按**帧数/24** 精确截断、再用 concat 列表拼：

```
# 逐段（时长取 frames/24，不要用容器时长，它含 AAC 补白）
ffmpeg -y -v error -i clip.mp4 -t {frames/24} -vn -ac 2 -ar 48000 -c:a pcm_s16le part.wav
# 拼接（PCM wav 用 -c copy 是安全的）
ffmpeg -y -v error -f concat -safe 0 -i parts.txt -t {total} -ac 2 -ar 48000 -c:a pcm_s16le bed.wav
```

**并且一定要核对**：`bed.wav` 时长必须**精确等于** Σ(帧数/24)。差几秒就说明有片段的音频比画面短
（常见于用 `anullsrc` 造静音时配了 `-frames:v`：视频一到帧数上限整个输出就终止，**音频被截短**，
实测 10.125s 的片子音频只有 7.70s）。黑场卡要**画面与静音分开生成再封装**。

### 视频仍用 `-c copy`，但要 `setpts` 重排

每段 AAC 的补白会让容器时长比内容长，累加起来成片会被拉长（本项目 +0.666s）。
渲染时给视频加重排，并把帧率模式设成 passthrough：

```
-vf "setpts=N/24/TB,<其它滤镜>" -fps_mode passthrough -r 24
```

## 1.5 纯黑卡 / 静音段：音轨会被截短

用 lavfi 造一张黑卡当片头，最自然的写法是

    ffmpeg -f lavfi -i color=black:s=768x1344:r=24 -f lavfi -i anullsrc=r=48000:cl=stereo \
           -frames:v 124 -t 5.1667 … out.mp4

结果是**画面 124 帧（5.167s），音轨只有 2.24s**——`-frames:v` 一到上限整个输出就结束，
音频被截断。单独 `ffprobe` 能看出来，混在一起就看不出来了。

正确做法：**分开造，再 mux**。

```
ffmpeg -f lavfi -i color=black:s=768x1344:r=24 -frames:v 124 -c:v libx264 … /tmp/v.mp4
ffmpeg -f lavfi -i anullsrc=r=48000:cl=stereo -t 5.1667 -c:a aac … /tmp/a.m4a
ffmpeg -i /tmp/v.mp4 -i /tmp/a.m4a -c copy -shortest out.mp4
```

验：`ffprobe -show_entries stream=codec_type,duration` 两条要**对得上**。

## 2. 统一调色

逐条生成的片段色调一定会漂。两层：

```
GLOBAL = curves=all='0/0 0.25/0.23 0.5/0.5 0.75/0.77 1/1',
         eq=saturation=0.93,
         colorbalance=rs=-0.02:bs=0.025:rm=-0.01:bm=0.012:rh=0.008:bh=-0.012
EXTRA  = 只给离群镜头（压暖、压暗、提对比）
```

`colorbalance` 的 `rs/gs/bs` 是阴影、`rm/gm/bm` 中间调、`rh/gh/bh` 高光。

## 3. 烧字幕（中文）

```
drawtext=fontfile='/usr/share/fonts/opentype/noto/NotoSerifCJK-Bold.ttc':
  text='…':x=(w-text_w)/2:y=606:fontsize=31:fontcolor=0xE8E4DC:
  shadowcolor=black@0.85:shadowx=2:shadowy=2:
  alpha='if(lt(t,ST+0.5),(t-ST)/0.5,if(gt(t,EN-0.5),(EN-t)/0.5,1))':
  enable='between(t,ST,EN)'
```

- `drawtext` 的文本里 **`\ : , ; ' [ ]` 要转义**，`%` 要写成 `\%`；中文标点不用转义。
- 淡入淡出用 `alpha=` 表达式，比 `fade` 滤镜更好控（`fade` 会整体变黑）。
- 章节卡压在水墨/复杂画面上要加 `box=1:boxcolor=black@0.38`，纯阴影对比度不够。
- 滤镜多时把滤镜链写进文件，用 `-filter_complex_script`，避免命令行长度与转义地狱。

## 3.5 libass 的五个坑（会让字幕/卡片"完全不显示"或"位置不对"）

1. **边距字段留空 → 整条事件被丢弃**。`Dialogue: 0,t0,t1,style,name,,,,text` 里
   MarginL/MarginR/MarginV 三个空字段会让 libass **直接跳过这条事件**，
   表现为"卡片一条都不显示"。必须写**显式**数值。这一条排除了很久才定位到，
   别从字体/样式方向查。
2. **`\move()` 写进了 Effect 字段** → 被当成普通文字**显示在画面上**
   （实测出现过 `1220,960,300,0,900}` 这种文字）。`\move` 是覆盖标签，必须放在 **Text 字段开头**。
3. **"上移避让"写进了 MarginL**（水平）而不是 **MarginV**（垂直）→ 避让永远不生效。
4. **双语拆成两条事件** → libass 的自动避让会把中英配错行（英文跑到别人的中文上面）。
   要**并入同一条事件**，行内用 `\fs` 缩小、`\c` 变暗，中英永远成块。
5. 按 `「」` 断句时先**保护引号内的整段**再切，否则会在引号中间断开。
6. **SRT + `force_style` 的缩放不可控。** 同样写 `Fontsize=19`、`MarginV=210`，
   在 1080×1920 上可能渲染成**一米大的字贴在天灵盖**（实测整块跑到画面 1/4 高度）。
   libass 会拿 SRT 没有 PlayRes 的默认值去缩放，字号和边距都不是像素概念。
   **要精确控制就写 ASS**：带上

       [Script Info]
       PlayResX: 1080
       PlayResY: 1920

   之后 `Fontsize=62` 就是 62 个像素、`MarginV=400` 就是从底往上 400 像素，所见即所得。
7. **一个 filtergraph 里串两个 `subtitles=` 会失败**（标题层 + 字幕层这么写，报 filter 配置错误）。
   把两层的 Dialogue 事件**合并进同一个 .ass**，只留一个 `subtitles=`。

## 4. 响度与峰值

- **全片用两遍 `loudnorm` + `linear=true`**：单遍是动态处理，会把逐镜的音量关系重新揉回去
  （本轮实测：无旁白的镜头被莫名拉低 4.7dB）。流程：
  `-af loudnorm=I=-16:TP=-1.5:LRA=11:print_format=json -f null -` 量 → 带 `measured_*` 线性施加。
- **`volume=` 是线性倍数不是 dB**：`volume=11.2` 是 +21dB，要写 `volume=11.2dB`。
- **`alimiter` 的 `limit` 是线性值**（−1.5dBFS → `0.84`），且默认 `level=true` 会把电平顶上去；
  写成 `alimiter=limit=0.76:level=disabled`。
- **AAC 解码会过冲**：给 TP 留约 1dB 余量，否则量出来是 −1.1 而不是 −1.5。
- 质检：`ffmpeg -i out.mp4 -af ebur128=peak=true -f null -` 看集成响度与真峰值。
- **`loudnorm` 内部会升采样，裸输出变成 96kHz**。高采样率 AAC 兼容性差（部分播放器/平台拒收或重编码）。
  最终编码**显式加 `-ar 48000`**；顺带注意重采样后真峰值还会再降一点。
- **`alimiter` 的门限必须按素材重新标定**，不能沿用上一版的数。同一套 loudnorm 参数下实测：
  0.70 → 真峰值 −1.1（**超标**）、0.62 → −2.0（合格）、0.56 → −3.1（响度被拖低）。
  办法：拿 premix 跑 0.70/0.62/0.56/0.50 四档，选"真峰值 ≤ −1.8 且响度最接近目标"的。
- 若 premix 的峰值比响度高 8 dB，线性 loudnorm 一抬就必然被限幅吃掉响度——
  这时该改目标或改限幅，而不是硬抬。

## 4.5 字号与字体（1080p 起步值）

- **正文字幕 44px**、**引文 48px**、出典 32px。34px 会被用户回一句"字幕偏小"。
- **介绍性文字要换字体**，否则和台词分不开：字幕用宋体（Noto Serif CJK），
  人物/章节卡用**黑体**（Noto Sans CJK）并更大一号。实测可用值：人物卡人名 52px、身份行 32px。
- 字体只用系统里**真实存在**的：先 `fc-list :lang=zh` 看。写了不存在的字体名，libass 会静默回退。

## 4.8 字幕行宽：先算能放几个字

1080 宽的字幕区，去掉左右 margin 之后大约 940px。中文字宽 ≈ 字号，所以

    每行字数 ≈ 940 / 字号

`Fontsize=62` → **最多 15 字，实际按 ≤11 字排**（留出标点与抗锯齿余量）。
`Fontsize=78` → 只能放 12 字。写成 16 字一行会直接顶出画面两侧。

所以断句要先按"每行 ≤11 字"来切，**允许一行字幕拆成上下两行**（`\\N`），
不要为了"一句话一条"把行撑爆。实测 14 镜 72 秒，两行制比单行制少一半的翻页次数，读起来更稳。

## 5. 画幅与竖屏

- 竖屏裁切：`crop=414:736:433:0,scale=1080:1920:flags=lanczos`（中心安全区）。
- ⚠️ **横屏烧好的字幕在竖屏裁切里会被切掉左右**（本轮实测："公元548年冬天"被切了头）。
  两种正解：先在竖屏画布上 `pad` 再加字；或者给竖屏做**独立分镜版**而不是裁一刀。
- 精确 16:9：H3 侧输出常是 1280×736（1.739:1），交付前 `crop=1280:720:0:8` 再 `scale`。
### 竖屏原生生成 → 1080×1920：`scale=-2:1920` + `crop`，别 `pad`

H3 竖屏原生出的是 **768×1344（0.5714）**，目标 9:16 是 0.5625，两者差 1.6%。
两种收法：

| 写法 | 结果 |
|---|---|
| `scale=1080:-2,pad=1080:1920` | 缩到 1080×1890，**上下各 15px 黑边** |
| `scale=-2:1920,crop=1080:1920` | 缩到 1097×1920，**左右各裁 8px**，无黑边 |

后者更好：8px 的裁切肉眼不可见，而 15px 的黑边在纯黑镜头的边上会被看出来
（画面抖动时黑边跟着跳）。除非你**故意**要留边，否则不要 pad。

顺带：竖屏原生生成比"横屏拍完中心裁一刀"清晰得多——768 宽裁出来的 432 宽再放大到 1080，
是 2.5 倍上采样，手机上能看出糊。**主发哪个平台，就用那个画幅原生生成。**

## 6. 对照表与总览图

- **分镜对照表**：每条取中点帧，`scale+pad` 统一到 640×360，`xstack` 拼网格，`drawtext` 烧镜头号。
- **静帧总览图**：同一套 xstack 逻辑，输入换成 PNG。
- ⚠️ `--out` 这类参数是**相对当前工作目录**的：在项目根目录跑却传了 `sheet.png`，图会落在根目录而不是 `out/`。
  要么传全路径，要么写完检查一遍。

## 7. 交付前必做的七项核对

1. **抽帧**：每条镜头取首/中/尾三帧，确认没有崩坏（AI 生成会在运动中崩）。
2. **响度**：集成响度 −16 LUFS、真峰值 ≤ −1.5dBFS。**横屏/竖屏/双语三个版本各测一次**。
3. **时长**：成片总长与设计稿一致；改过任一条片段就要重排时间线并复核字幕入点。
4. **帧数**：`nb_frames` 必须等于 Σ(设计帧数)，且约等于 `总秒数×24`。
5. **音画等长**：音轨时长 == 视频时长。差 >0.1s 说明有片段的音频短了（见 §1 的 AAC/静音坑）。
6. **画内口播**：在每个台词时间窗里量 RMS，`>0.01` 才算有声；全零 = 那一镜的台词没进成片。
7. **黑场白名单**：纯黑卡片的"黑边告警"是误报，校验脚本要把这几个镜号放行。

## 7.5 我自己反复踩的"非 FFmpeg"的坑

- **`f-string` 在 `subprocess.run()` 之前就求值了**：`run(cmd, f"合片 {dur(raw)}s")`
  打印的是**上一次**的旧文件时长，看起来像"渲染没生效"。要先跑再算，或把日志放到 run 之后。
- **用 `-ss` 抽段做"验证渲染"会重置 ASS 时间戳**，字幕的时间与位置全错，结论毫无意义。
  验证字幕必须**从 t=0 渲染**再看指定时刻。
- **数文件个数判断进度会骗人**：目录里已有上一轮产物，`ls | wc -l` 早就够了。
  必须按**镜号 + 帧数**逐条核对（`ffprobe -show_entries stream=nb_frames`）。
- **`volume=` 是线性倍数不是 dB**；**`alimiter` 的 `limit` 是线性值**——`volume=11.2` 等于 +21dB。
- **`--out` 这类参数是相对当前工作目录的**：在项目根目录跑却传 `sheet.png`，图会落在根目录。
