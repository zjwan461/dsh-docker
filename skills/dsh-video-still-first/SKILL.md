# 静帧先行与跨镜头一致性

## 1. 管线：先图后视频

```
身份锚点（文生图，多张选一）
   └→ 场景静帧（image_edit，大改动）
        └→ i2v（静帧当首帧，只写"运动"）
             └→ 统一调色 → 合片 → 字幕/响度
```

- **i2v 的一致性最好**：画面长相由首帧决定，提示词只负责运动。
- **t2v 会换人换风格**：本轮实测同题材同 seed，t2v 生成的是**另一个人 + 另一套色调**。
  要角色一致就别用 t2v；纯空镜/氛围镜可以。
- **r2v 是跨镜头锁角色的正确工具**（多张参考图 + `<Picture N>`），但参考图本身要先做好。

## 2. image_edit 的硬规则

**大改动有效，微调退化。** 每次调用都给一个真实的场景改动（换环境、换服装、换机位），
不要提"保持原样，只微调 X"——那类指令出的是斑驳、叠影。

**⚠️ 最重要的一条：移除指令必须逐项点名。**

> 本轮真实事故：一句 `"Remove every person from the boats, and remove all torches, fire,
> smoke and banners"` 把**划桨的兵**和火把旗子一起清掉了。
> 结果"八千兵渡江"这一镜被拍成**三条无人空船**，而同镜旁白正是
> "一个人带着八千兵渡过了长江"——**画面与旁白直接矛盾，是叙事错误，不是风格问题**，
> 而且一路过了自动检查、直到人看片才发现。

规则化：

| 要移除的东西 | 写法 |
|---|---|
| 该走的（火把、旗帜、烟、现代物件） | 逐项点名移除 |
| 该留的（人、船、桨、甲胄） | **同时正向描述**要留下的主体与数量，并在负面词里**不要**出现 `people` / `person` |

改完必须**回头看原需求**：这条镜头要表达的事实（多少人、什么方向、白天黑夜、有没有船）还在不在。

## 2.5 静帧必须和运动提示词讲同一件事

i2v 的首帧是**硬约束**，但模型会**努力去满足提示词**。两者冲突时它会当场跳：

> 本轮真实事故：C5 的内容改成了"皇帝写伪书"，静帧却还是旧的"侯景冷脸"，
> 而运动提示词按新内容写成了皇帝。结果**第 0.05 秒就跳成了皇帝**——
> 看起来像"静帧没生效"，其实是静帧与提示词互相打架。

规则：**改一镜的内容，静帧和运动提示词必须一起改**。只改一边，出来的一定是四不像。
跑完取第 0 帧和意图静帧比差（见 §2.7），差值大就说明没对上或开场就跳了。

## 2.6 别让连续两镜从同一个锚点派生

同一张锚点、两句相近的提示词（"同一人、同灯、同帐"，只差一个表情词），
出来的两张静帧**几乎一模一样**（本项目 C3/C4/C5 三镜长得几乎相同，等于连续三镜没换画）。

做法：
- 相邻镜头**换构图幅度**（近景→中景→侧背），不要只换形容词；
- 或者其中一镜改从**另一个源**派生（换场景锚点、换角度）；
- 派生完把相邻几镜**并排放一张对照图**看，别单张看。

## 2.7 静帧"喂进去了没有"必须验，而且要防缓存

**ComfyUI 的 `LoadImage` 按输入参数缓存。** 文件名不变 = **命中缓存、复用上一张图**，
磁盘上的文件换了也不生效。

> 本轮真实事故：C4/C5 换了新静帧重跑，出来的视频还是旧画面（C4 仍是"毛笔写字"）。
> 我一度以为是 i2v 没吃到首帧，查了很久。

两条一起做：

1. **上传时文件名带内容哈希**：`C4_1_47f47cdf.png`。参数一变缓存键就变，必然重新加载。
   （注意：改文件名要**只改上传用的名字**，读文件还得读原路径——本轮改错过一次，
   改完名拿新路径去读，直接 FileNotFoundError。）
2. **跑完验首帧**：取视频第 0 帧，与意图静帧缩到同尺寸算平均绝对差，>32 就报警。

## 2.8 多个人物同框：从"角色最硬的那个"派生

要让两个已知角色出现在同一画面里，二选一：

- **单人锚点 + image_edit 加人**：从**最难保持身份**那个角色的锚点出发，让 edit 把另一个人加进去。
  构图选**过肩**或**侧向对坐**，让"加进来的人"只露肩背/侧脸——身份要求一降，成功率就上去了。
  本项目 C3（侯景跪在前景、只露肩背）与 E2b（侧向对坐、两个都露但都不居中）都是这么成的。
- **r2v 带多张参考图**：`refs` 传 2 张锚点，提示词里按顺序指代。适合两人都要正脸特写时。

⚠️ 同框之后还要防模型**自己加切换**（它会按台词切到说话人特写）——
提示词要把"不切"说到极致，详见 `dsh-minimax-h3-video`。

## 2.9 锚点图要"能接"：正面、均匀光、干净背景

锚点不只是"像不像"，还要"贴不贴"。**侧脸、逆光、杂乱背景是换脸边缘闪烁和融合不自然的主因**——
这几条在 i2v/r2v 里都会被放大成画面问题。

- 选锚点优先**正面、光照均匀、背景简洁**的那张；定妆图别在纹理很杂的环境里拍。
- 提示词里补一句：`consistent character, natural edge blending, no distortion`。
- 源素材/提示词避免快速运镜和复杂遮挡；大动作、手部细节是崩坏高发区。
- 边缘还是闪：把步数提到 30，或对结果帧序列做一次轻度时域平滑。

H3 的换人是**条件化重绘**（按参考图重画整段），不是逐帧 face swap：对侧脸/遮挡的鲁棒性更好，
但仍要抽卡。所以"锚点选得对"比"多跑几次"便宜。

## 3. 交付前的叙事一致性核对（逐镜过）

自动检查只能证明"有人在说话""画面没崩"，**证明不了"画面说的和旁白说的是同一件事"**。逐镜问四个问题：

1. **人数/主体**：旁白说"八千兵"，画面里有没有人？说"只有他一个人"，画面里有几个？
2. **道具状态**：桨在不在水里、火把是灭的还是燃的、门是开还是关。
3. **时间与光**：脚本写"夜"，画面是不是白天（本轮另有镜头写着夜江、实际出的是晨雾亮调）。
4. **方向与位置**：进城/出城、在船上/在岸上，别左右颠倒。

发现问题先分类：**叙事错误**（必须重做，改静帧再重跑 i2v）vs **风格偏离**（可接受或调色解决）。
重做时先改静帧——根因通常在静帧，不在 i2v。

### 3.5 让"第一次看的人"看得懂（用户最常提的一类问题）

"没头没尾"不是画面问题，是**信息顺序**问题。逐条查：

1. **人物第一次出现就要给名字**。不要用"一个人""他"撑到第 56 秒才揭晓。
   旁白第一句就点名，同时配一张**人物卡**（名字 + 一行身份）。
2. **文言/典故要翻译**。旁白念原句的同时，必须**把意思说出来**；原句可以另做一张引文卡上屏。
   反例：只念"不意昭阳殿，化作单于宫"而不解释，观众不知道是"皇宫会变成胡人的宫殿"。
3. **关键动作不能只在画面里**。"他拉弓射向自己的儿子"这种决定性动作，
   光靠画面观众可能没看懂——旁白要**说出来**。
4. **陌生概念换成白话**。给普通观众看就别说"门阀"，说"那些世代做官的大家族"。
5. **卡片不能和旁白打架**。卡片写"548年·冬"、旁白说"三年零七个月之后"，
   观众会以为卡错了。要么把卡改成时间跨度，要么挪到旁白不冲突的位置。
6. **因果链要有前因**。"他要造反"之前必须交代：为什么、被谁逼的、导火索是什么。
   本项目原版把"起兵"整个 beat 漏掉了，观众看到的是"求亲被拒"直接跳到"围城"。
7. **介绍性文字要打字排区分**（换字体 + 更大字号），别和台词混在一起。

做法：把全片字幕按时间排成一条**连续解说稿**通读一遍——这是发现"没头没尾"最快的办法。

## 4. 重做一镜的最小代价路径

1. **只重出静帧**（1 次图片调用），不要重跑整片；
2. **保持帧数不变**，时间线、字幕入点、总长都不受影响（本轮就是这样把 S2 修好的）；
3. 新片段用**新文件名**（如 `*_S2v3_*.mp4`），旧片段留档对照，不要覆盖；
4. 调色/合片脚本若按"同镜多版本"取文件，应改成**按修改时间取最新**，避免手工改脚本。
5. **只改提示词、不改帧数时，进度核对会误判"已完成"**（帧数一样）。
   重做清单里要能区分"帧数不符"和"内容要重做"两种原因，后者必须**强制**重跑。
6. 重跑前先做**静帧与视频的对应表**（镜号 → 静帧文件 → 视频文件），
   避免改了静帧却跑了旧视频（本轮 C4/C5 就吃了这个亏）。

## 5. 角色一致性做法

- 建**身份锚点**：同一角色多张候选里选一张正脸半身当锚点，之后所有场景静帧都从它派生。
- 提示词里**明确复用同一主体**（`<Subject N>`），并把"脸不一样"写进负面词。
- 每隔几镜做一张**一致性对照表**（把同一角色每次出现拼在一起），漂没漂一眼就能看出来。
- 交付说明里写清"哪几镜是同一个人"，便于复核。
